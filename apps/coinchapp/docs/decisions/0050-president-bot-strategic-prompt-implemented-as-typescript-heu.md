# 0050 — Président bot: strategic prompt implemented as TypeScript heuristics, not a live LLM call

Date: 2026-09-15
Status: Accepted
Decision: User supplied an elaborate French "Président master player" system prompt intended for an LLM. Given a choice, they picked reimplementing its strategic principles as deterministic rules in `lib/president/bot.ts` (`chooseAction`) over wiring a real per-move LLM call. `chooseAction` now: (1) exchange - gives away true singletons before ever breaking a pair/triple/quad (`chooseReturnCards`, sorted by group size then rank); (2) play - never spends a card that fractures a group or a "master" rank (2/Ace, or their revolution mirror) unless the combo is otherwise free, or the endgame is looming (`comboCost`, `shouldTakeThePile`, `endgameLooming`: own hand `<= 3` cards, or an opponent down to `<= 2`); otherwise it voluntarily `PASS`es via the pile's existing `canPass` (true whenever not leading a fresh pile) to protect the combo/card for later.
Context: The prompt described a full LLM agent (JSON turn state in, `<Analyse>` + `ACTION:` out) with card-counting memory of fallen 2s/Aces. Asked whether to actually call an LLM per bot move or translate the same principles into local rules; user chose the local-rules path.
Rationale: The current architecture (`docs/TECH.md`) runs Président bots synchronously, client-side, with no network call - required for the offline-first local solo mode (PWA) and instant turns. A real LLM call would need choosing/configuring a provider, a server-held API key (bots currently need no secrets), per-move network latency, and a per-game cost, and would break the offline solo game entirely - all of that is a stack/vendor decision the user did not ask to make. The prompt's card-counting principle (remembering which 2s/Aces already fell) was dropped: `GameState`/`PlayerView` never retains a log of past plays within a round (only past rounds' `roundHistory`), so honoring it would require a new tracked field (a data-model change) for a heuristic gain not requested; every other principle (protect combos, hoard masters, spend when the endgame looms) maps onto data already in `PlayerView` (`myHand`, `legalCombos`, `canPass`, `handCounts`, `revolution`).
Consequences: No new `GameState`/`PlayerView` field, no secrets, no async bot path - `advanceBots`'s synchronous loop and `decidePresidentAction`'s `Promise.resolve` wrapper are unchanged. Bots can now voluntarily `PASS` even holding a legal combo (previously they never did); a 50-seed sweep test (`engine.test.ts`) confirms this never starves `advanceBots`'s 500-iteration guard. 9 new `bot.test.ts` cases lock in the pair-protection, master-hoarding, and endgame-override behaviors.
Alternatives_Rejected: A real LLM call per bot move (rejected by the user - vendor lock-in, breaks offline play, adds latency/cost); adding a `playedCards`/discard log to `GameState` to support literal 2/Ace counting (data-model change for a principle no existing `PlayerView` consumer needs, deferred - not requested once the LLM route was declined).
