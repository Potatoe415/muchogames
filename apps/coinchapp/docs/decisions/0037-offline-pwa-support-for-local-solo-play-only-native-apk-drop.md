# 0037 — Offline PWA support for local (solo) play only, native APK dropped

Date: 2026-07-19
Status: Accepted
Decision: Added a Web App Manifest (`app/manifest.ts` + `app/icon.png`/`app/apple-icon.png`/`public/icons/*`), a hand-written service worker (`public/sw.js`, registered by `components/ServiceWorkerRegistration.tsx`), and localStorage persistence for in-progress local matches (`lib/client/localGamePersistence.ts`, wired into `useLocalGame.ts` and `useLocalBouillaGame.ts`). Scope is deliberately limited to the local/solo mode (vs bots) - online and ad-hoc modes are untouched and remain impossible to play without a network connection.
Context: User wants to play Coinche/Bouilla offline (e.g. on a plane) on iPhone/Android without the page breaking on reload. Explored wrapping the app as an Android APK (WebView shell, Capacitor) but the user chose to stay in the browser instead.
Rationale: Online/ad-hoc modes are server-authoritative by design (`docs/TECH.md`) and cannot work without a network, no caching trick changes that. Local mode already runs the rules engine and bots fully client-side with zero network calls, so it's the only mode a service worker + local persistence can actually make reload/relaunch-proof. Service worker strategy: network-first for navigations (so online users always get the current deploy's HTML/hashed assets - no manual "new version" banner or cache-busting needed) and cache-first for `/_next/static/*` (content-hashed, safe to cache forever). Game state resume: `savePersistedGame` writes to `localStorage` on every commit and clears itself once `phase === "finished"`; resuming is the default on any mount (covers reload and full app relaunch), and is explicitly cleared before any deliberate "new game" action (`app/local/page.tsx`'s `startLocalGame`, and both games' in-match "rejouer" `onReset`) so an abandoned save can never resurface by mistake.
Consequences: New files only, no new dependencies. `lib/coinche`/`lib/bouilla`/server code untouched. Two call sites (`useLocalGame.ts`, `useLocalBouillaGame.ts`) hydrate saved state inside a mount-only effect with a scoped `eslint-disable-next-line react-hooks/set-state-in-effect` (same precedent as the pre-existing, still-unfixed violation in `useMatchStats.ts`) rather than moving the read into the `useState` initializer, to avoid an SSR/hydration mismatch (the initializer's output must stay deterministic from `(targetPoints, seed, scoringRules)` alone to match the server-rendered HTML). `docs/TECH.md` not yet updated - offline/installable capability pending user confirmation to record it there.
Alternatives_Rejected: Native Android APK via Capacitor with a WebView (either pointing at the live URL, or with the solo game's assets fully bundled offline) - would have been the most bulletproof "zero network, ever" option, but the user preferred to stay in the browser rather than ship/maintain a separate native build. `next-pwa`/Workbox - unnecessary dependency for a strategy this small; a ~90-line hand-written `sw.js` covers exactly the two caching rules needed with no build-time integration risk against Turbopack.
