# 0039 — Bot thinking-time setting (800ms-4s), shared by both games and every mode

Date: 2026-07-22
Status: Accepted
Decision: Added `GameSettings.botThinkMs` (800-4000ms, default 800, step 200 - `DEFAULT_BOT_THINK_MS`/`MIN_BOT_THINK_MS`/`MAX_BOT_THINK_MS`/`BOT_THINK_MS_STEP` in `lib/supabase/types.ts`), exposed as a new slider in `GameSettingsPanel.tsx` (always rendered, not gated behind `coincheFields`, since it applies to both games). For Coinche it is the ISMCTS play search's wall-clock budget (`BotOptions.timeBudgetMs`, `lib/client/bot.ts`) - a higher value means a stronger search, not just a longer wait. For Bouilla, whose heuristic bot is instant, it is a pure pacing delay. Threaded through every mode that runs bots: online (`useBotRunner.ts` reads `gv.settings.botThinkMs`, passes it to `useBotWorker`, and paces Bouilla's instant `decideBouillaAction` with `Promise.all([decide, wait(thinkMs)])`), local (`useLocalGame`/`useLocalBouillaGame` gained a `botThinkMs` parameter, replacing the previous hardcoded `BOT_THINKING_MS = 500`), and ad-hoc P2P (`useP2PHost` reads it from `settings`; `useP2PBouillaHost` gained a new optional `botThinkMs` config field, since that hook previously took no settings at all). `useBotWorker`'s Web Worker request/response (`botWorker.ts`) now carries `BotOptions` (`{ punch, timeBudgetMs }`) instead of always using the hardcoded 800ms default baked into `chooseClientAction`'s own default.
Context: Same user report that prompted the `useBotWorker.ts` worker-death fix earlier this session (bots occasionally stalling 5-10s then playing a card that looks close to random) - the user asked to make the bot "thinking" time itself configurable, min 800ms (previous fixed ISMCTS budget) to max 4s.
Rationale: `useBotWorker`'s watchdog (previously a fixed 4000ms) had to become budget-aware (`watchdogFor(timeBudgetMs) = max(4000, timeBudgetMs + 3000)`), otherwise a 4000ms `botThinkMs` setting would make a perfectly healthy worker look "stuck" and get wrongly abandoned to the main thread on every single bot turn. `runBotLoop`'s existing `thinkingMs` parameter (shared by local + ad-hoc, both games) was already the right shape for the local/ad-hoc side; the online path had no equivalent pacing for Bouilla, so a `wait()` was added there to match. One setting field (not two per game) since both `botPunch`/`stillThereTimeoutSec` already established the pattern of one shared, optional `GameSettings` field read contextually per game/mode.
Consequences: `games.settings` jsonb gains an optional `botThinkMs` key (no migration; absent = 800ms, unchanged behavior). Local and ad-hoc Bouilla setup screens, which previously hid `GameSettingsPanel` entirely (`{!isBouilla && ...}`), now always render it (with `coincheFields={!isBouilla}`) so the new slider (and nothing else, for Bouilla) is reachable there too - same pattern the online Bouilla setup screen already used. `sanitizeSettings`/`sanitizeCoincheSettings` (`lib/server/actions-lobby.ts`) clamp+snap any incoming value to `[MIN_BOT_THINK_MS, MAX_BOT_THINK_MS]` on the `BOT_THINK_MS_STEP` grid.
Alternatives_Rejected: A separate setting per game (rejected as unnecessary duplication - the slider's meaning differs slightly per game, but the mechanism, bounds, and UI are identical); leaving the online Bouilla path un-paced (rejected - would make the slider a no-op for online Bouilla specifically, inconsistent with every other mode/game combination).
