# 0062 — Bootstrap v10.1 context architecture alignment

Date: 2026-09-22
Status: Accepted
Decision: Aligned this app's context architecture with bootstrap prompt v10.1 (ALIGN mode, upgrading from the v9-style layout adopted in decision 0001): split the flat `docs/DECISIONS.md` into `docs/decisions/NNNN-slug.md` files + `docs/decisions/INDEX.md` (verbatim, one file per entry, 61 decisions); added `docs/ARCHITECTURE.md` (merged from `docs/TECH.md`, including the "Card games — shared base" and "simulate instant/local feel online" sections verbatim), `docs/SECURITY.md`, and `docs/DEBUGGING.md`; added `docs/_templates/` and `.claude/settings.json`; rewrote `AGENTS.md` and `STATE.md` to the v10.1 structure while keeping every app-specific rule (`data-id`, card-game shared base, optimistic-play hooks); condensed `docs/BACKLOG.md` (dropped `Done`, merged `Later` into `Next`). Applied as part of a repo-wide pass also covering the root `muchogames` repo and `apps/tranquil`, at the user's explicit choice (all three at once, on `main`, no dedicated branch).
Context: The user supplied `bootstrap-prompt_v10.1.md` and asked to apply it to the `muchogames` project as a whole. This app already used the AGENTS.md-centric protocol from bootstrap v9 (decision 0001), so this was the explicit "upgrade from bootstrap v9" path (bootstrap v10.1 §3.4), not a fresh CREATE.
Rationale: ALIGN mode's own rules (never overwrite; merge; keep what works) meant `docs/DATA_MODEL.md` was kept as-is (already close to the v10.1 shape) and the real module boundary (`lib/<game>/` pure rules engines, not `src/modules/`) was documented as-is rather than restructured. The `docs/DECISIONS.md` → per-file split was done with a small parser script (not manual transcription) to guarantee verbatim wording/dates across all 61 entries without transcription risk — this file was the largest of the three repos' decision logs.
Consequences: `docs/TECH.md`, `docs/DECISIONS.md`, `CLAUDE.md`, and `.cursor/rules/000-router.mdc` are now superseded but kept on disk pending explicit user confirmation to delete. Future decisions are logged as individual files under `docs/decisions/`, indexed in `docs/decisions/INDEX.md`. No application code, game logic, or product scope changed in this pass.
Alternatives_Rejected: Restructuring `lib/<game>/` into a `src/modules/` tree to literally match the v10.1 template — rejected, the existing per-game-engine layout already serves the same purpose and ALIGN mode explicitly forbids reorganising working code to fit a template. Deleting the superseded files immediately — rejected, ALIGN mode requires explicit user confirmation before any deletion. Doing this app alone without the root repo/`tranquil` — rejected, the user chose all three in one pass.
