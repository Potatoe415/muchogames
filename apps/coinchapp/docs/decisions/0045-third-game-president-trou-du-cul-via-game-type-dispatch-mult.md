# 0045 — Third game "Président" (Trou du cul) via `game_type` dispatch, multi-card actions as new parallel actions

Date: 2026-09-10
Status: Accepted
Decision: Added a third card game, "Président" (a.k.a. Trou du cul: 4 players, no teams/trump, singles/pairs/triples/quads by rank, a quad triggers a "revolution" that inverts rank order for the rest of the round, a forced card exchange at the start of every round after the first based on the previous round's finish order, cumulative finish-rank scoring over a fixed number of rounds - lowest total wins) as a fully independent rules engine `lib/president/` (types/cards/deal/combos/play/exchange/scoring/engine/bot/redact, mirroring `lib/bouilla/`'s layout), wired through the same `games.game_type` discriminator used for Bouilla (2026-06-12/2026-07-16 entries). Two deliberate departures from that precedent: (1) Président's moves are multi-card (1-4 cards) or a pass, unlike Coinche/Bouilla's always-one-card `playCard` - rather than reshape the shared single-card `playCard`/`WireCard`/`useOptimisticPlay` path (used by two working games, zero regression budget), Président got its own parallel Server Actions (`playCombo`, `pass`, `submitExchangeReturn`) and its own multi-select UX in `PresidentTable.tsx`, not `useOptimisticPlay`. (2) The forced exchange is modeled as two sequential turns (President returns first, then Vice-President) rather than concurrent, so it fits the single-`turn: Seat` model every shared subsystem (idle-timer, stale-turn takeover) already assumes.
Context: User provided a full written plan for this game up front (rules, architecture recipe, explicit decisions) and asked for an end-to-end implementation (engine, server dispatch, client adapters, ad-hoc P2P, UI, routing, docs) in one pass, reusing every game-agnostic layer already proven by the Coinche->Bouilla precedent.
Rationale: The rules layer (revolution/exchange/combo-shedding vs Coinche's bidding/trump/teams and Bouilla's fixed-round penalties) is again genuinely incompressible, so a third pure engine is the right boundary - the exact pattern the 2026-07-16 Bouilla entry predicted ("Adding a third game means: one more `lib/<game>/` engine, one more `<game>EngineAdapter.ts`, one more `<Game>Table.tsx`, and one more `game_type` branch at the same handful of dispatch points"). Everything below the rules layer (repo/view/presence/realtime/WebRTC transport, UI primitives like `PlayingCard`/`PlayerBadge`/`EmojiButton`/`TrickStage`) needed zero changes beyond widening the same discriminated unions and adding a third branch at the same dispatch points (`game-dispatch.ts`, `actions-lobby.ts`, `actions-game.ts`, `idle-timer.ts`, `view.ts`, `GameRoom.tsx`, `Lobby.tsx`, `AdHocLobby.tsx`, `GameSettingsPanel.tsx`, `RulesModal.tsx`). Hitting a third instance of two DRY call-outs also triggered the repo's own "extract before adding a third" rule: `useLocalGame.ts`/`useLocalBouillaGame.ts`'s ~90% duplicated scaffolding (state/ref/persist/runBots/mount-resume) was extracted into a generic `useLocalCardGame<TState,TView,TAction>` hook (config: adapter, persistence key, initial-state factory), with all three local-solo hooks now thin wrappers around it; the Bouilla-only `bouilla-round-gate.ts` (end-of-round readiness gate) was similarly generalized into `lib/server/round-gate.ts`, since Président needed the identical "wait for every human or auto-advance after N seconds" mechanism.
Consequences: `GameType` is `"coinche" | "bouilla" | "president"`; `GameSettings` gains an optional `presidentRoundsToPlay` (default 4, options 3/4/5/6/8, `DEFAULT_PRESIDENT_ROUNDS_TO_PLAY`/`PRESIDENT_ROUNDS_OPTIONS` in `lib/supabase/types.ts`) - Président's exchange mechanics are otherwise fixed, no per-game config beyond the shared `stillThereTimeoutSec`/`botThinkMs`. `BotMove`/`HeuristicMove` (`game-dispatch.ts`) widened from a 2-shape union to a 5-shape one (`bid`/`play`/`combo`/`pass`/`exchangeReturn`). Bot AI is heuristic-only (no ISMCTS/Worker), following the Bouilla precedent - the combo search space is large but a simple greedy "smallest legal combo, conserve big sets" heuristic is adequate for a shedding game. **Ad-hoc P2P host hooks were NOT generalized**: `useP2PHost.ts`/`useP2PBouillaHost.ts` were already two full parallel ~200-line files at N=2 (never generalized then either); a third parallel `useP2PPresidentHost.ts` was added following the same shape rather than risk a refactor of working WebRTC code - the resulting 3x duplication is logged below in `docs/BACKLOG.md` as a follow-up, not fixed now. `docs/PRODUCT.md`/`docs/TECH.md` not edited autonomously (per file ownership rule) - flagged for user confirmation of wording, same as the still-outstanding Bouilla gap noted in those files' Open_Questions/STATE.md.
Alternatives_Rejected: Reshaping `playCard`/`WireCard`/`useOptimisticPlay` into a generic multi-card action (would touch the two working games' hot path for a single new game's benefit, against the explicit zero-regression-budget constraint); modeling the exchange as concurrent (would require either a new "everyone acts at once" state shape shared subsystems don't understand, or per-seat sub-state the idle-timer/stale-turn code would need bespoke branches for); generalizing the ad-hoc P2P host hooks now (bigger, riskier refactor of working WebRTC code than this feature's own scope, and the team already chose duplication once at N=2 - deferred, not rejected outright).
