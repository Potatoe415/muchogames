# 0052 — La Bataille Corse table redesign + configurable 32/54-card deck (jokers)

Date: 2026-09-16
Status: Accepted
Decision: Following several rounds of live user feedback, `BataillecorseTable.tsx` moved from "3 separate buttons + plain single-card stock icons" to a single tap-driven interface: the slap "button" is now a very light circle wrapping the pile itself (tapping the cards is the slap gesture), and the flip ("Jouer") action moved onto the player's own stock pile directly - there is no standalone "Jouer"/"Retourner" button left. Each stock pile now renders as a layered card-back "deck" (own pile scaled 1.5x) with the remaining count as a bare number on the front card's back, and pile history cards gained a mirrored right-side rank/suit index (new opt-in `PlayingCard` prop `showRightIndex`, every other game unaffected) so a card peeking out from behind the top one stays readable regardless of which side is visible. A transient "reaction time in seconds" readout (e.g. "0,133 s", locale-formatted decimal comma/point) now shows for a few seconds after every slap attempt. Separately, the deck is now configurable per the user's request: 32 cards (piquet-style, 7 and up, no jokers) or 54 cards (full 52-card pack + 2 jokers, the new default) - a joker is a challenge rank worth 5 tribute attempts, like J/Q/K/A. Dedicated splash art (`public/bataillecorse-full.jpg`) was added for both the `/bataillecorse` splash background and its home-grid tile; all 4 home-grid tiles became a taller `aspect-[3/4]` instead of a square, per a follow-up request.
Context: Iterative UI/UX polish requested live, one instruction at a time, immediately after the game's initial ship (see the entry above). The deck-size request came with an explicit "either 32 or 54" framing (no 52-only option kept) and no direction on jokers' tribute weight, so the traditional "joker = 5 attempts" value from the original rules research (see the initial "fourth game" entry's research) was reused rather than invented.
Rationale: A real timing bug was found and fixed along the way: the original `useEffect`-based "when did this client first see the open slap window" tracking ran after the browser's paint, late enough that a genuinely fast human reacting to the very frame that opened the window could tap before the effect committed, wrongly measuring 0ms reaction as if no window existed. Switched to `useLayoutEffect` (commits before paint) writing into a `ref` (not `state`) - reading a ref during render is disallowed by this codebase's stricter React Compiler lint rules, so the ref is only ever read from the `tapSlap` event handler, never render. Encoding jokers as an ordinary `Rank` value (`"JOKER"`) with no natural suit, rather than a new `Card` variant, kept every existing rank-comparison code path (tribute chaining, slap pattern detection) working unchanged - only `cards.ts` (deck construction, attempts table) and `PlayingCard.tsx` (rendering) needed to know about them at all.
Consequences: `lib/bataillecorse`'s `Rank`/`DeckSize` types, `buildDeck`/`deal`/`createInitialState` signatures, and `GameSettings.bataillecorseDeckSize` are new (default 54, changed from the initial ship's fixed 52 - see docs/DATA_MODEL.md). Existing tests asserting a fixed 52-card/26-card split were updated to the new 54-card/27-card default, plus new 32-card-deck cases. `GameSettingsPanel.tsx` gained a `bataillecorseFields` 32/54 toggle rendered directly under the shared bot-think-time slider, threaded through local/online/ad-hoc exactly like Président's `roundsToPlay`. No SQL migration (`games.settings` is opaque jsonb).
Alternatives_Rejected: A distinct `Joker` type/shape instead of an ordinary `Rank` value (rejected - would have forced every rank-comparison site in the engine to special-case it for no behavioral gain, since jokers behave exactly like any other challenge rank). Keeping the window-seen timestamp in a `useState` "adjust state during render" pattern like `usePileDisplay`/`usePileEnterDirection` elsewhere in this file (rejected - calling `performance.now()`, an impure function, during render is disallowed by the same lint ruleset that already governs this codebase, unlike those other hooks which only read already-known values).
