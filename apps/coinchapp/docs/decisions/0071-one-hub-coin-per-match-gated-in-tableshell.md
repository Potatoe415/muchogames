# 0071 — One hub coin per match, gated in TableShell

Date: 2026-10-03
Status: Accepted
Decision: Every match in the four games spends one hub coin (root `docs/PLATFORM_RULES.md`). `TableShell` takes an optional `match` and renders `MatchGate`, which calls the Server Action `startMatchCoin` once per match (the hub's `start_muchogames_match`, from the linked `mg-profile` or the hub's anonymous `?mgDevice=` id), shows "plus de pièces" and sends the player to the game's home when refused, and asks "Quitter la partie ?" before a `data-id="game-back-button"` link leaves a match in progress. Back/options controls now use the platform `data-id`s (`game-back-button`, `game-options-button`, `game-options-panel`).
Context: Owner request (2026-10-03): coins are spent per match started, not per hub launch, with one counter across every game; online players each pay when the match starts and again on a rematch.
Rationale: Every table of every mode (local, duel, ad-hoc, online) already renders through `TableShell` with a `GameView`, so one gate covers all of them without touching each mode's start flow. A match is charged when first seen `playing` and the mark is cleared when it is seen `finished`, which makes an online rematch in the same room a new charge and a reload free. Local games get a new random id per page load while their state is restored, so they are tracked per game (`local:<game>`).
Consequences: A local mid-match reset/reshuffle is not charged (same local key). A player who never sees an online match's `finished` state is not charged for the rematch that follows. Refusal happens after the table appears, not before. Admins are unlimited only once `ADMIN_USER_IDS` is set on this Vercel project. Any server error lets the match go on.
Alternatives_Rejected: Charging in each mode's start handler (four games × four modes, easy to miss one). Charging server-side in `startGame`/`rematchGame` (the server does not know each player's hub profile or device id).
