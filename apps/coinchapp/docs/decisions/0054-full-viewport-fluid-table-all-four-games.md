# 0054 — Full-viewport fluid table (all four games)

Date: 2026-09-17
Status: Accepted
Decision: Replaced the shared `max-w-[460px] min-h-[720px]` / `h-[720px]` phone-column table with a full-viewport `TableShell` (`100svh`, no max-width). Playing cards use `aspect-ratio: 2 / 3` and `clamp(4rem, 12svmin, 7rem)` for `lg` (same topology: HUD overlay on top, opponents around the oval, hand fan at the bottom). La Bataille Corse gained the same bottom safe-area spacer as the other games; HUD uses `env(safe-area-inset-top)`.
Context: User asked the table to fit every phone, tablet, and desktop browser - no longer a centered 460px column once there is horizontal room. Explicitly chose "the table grows and fills the screen" over side rails for score/chrome, and all four games in one pass.
Rationale: Percentage seat positions already on the oval scale for free once the scene is a flex child of `100svh`. `svmin` (not `cqmin` inside inherited custom properties, which resolved to 0 on the cards) keeps card size tied to the smaller viewport side without jumpiness from `dvh`. The 4rem floor matches the previous 64px `lg` card so phones do not shrink; the 7rem cap stops cards becoming placemats on a 27" monitor. Hand-fan overlap is preserved (absolute slots, step from measured card width).
Consequences: New `components/TableShell.tsx` and `lib/client/useCssVarPx.tsx`. `PlayingCard` / `CardBack` no longer use Tailwind `h-24 w-16` pairs. GameTable/Bouilla/President/Bataillecorse drop the 460/720 shell. DOM/CSS only - no Canvas/WebGPU. `docs/PRODUCT.md` still says mobile-first (not edited; confirmation needed if we want to mention tablet/desktop tables there).
Alternatives_Rejected: Side rails for HUD on tablet/desktop (user picked grow-the-table). `vmin`/`cqmin` on each card vs the window (would overflow a future constrained parent; `cqmin` in inherited vars didn't resolve). `dvh` (would reflow the slap circle when mobile chrome hides). Flex-wrap hands (would destroy the fan). Canvas/WebGPU.
