# 0060 — La Bataille Corse: face-to-face 1v1 duel mode, same device

Date: 2026-09-21
Status: Accepted
Decision: Added a third `/local` mode for la Bataille Corse only - a toggle ("Contre un bot" / "Face à face (2 joueurs)") in the existing setup screen, no new home-screen button. In duel mode both seats are real humans on one device: seat 1's whole corner (name, own reaction-time readout, own tappable stock) is rendered rotated 180deg so the player sitting across the phone reads it upright from their side; seat 0's corner is unrotated as before. The shared center pile stays neutral (unrotated, single instance) - like a real card on a table, glanced at from either side. The single slap hit-target is split into two invisible top/bottom halves over that same pile so a tap can be attributed to the correct seat (`onSlapTop` → seat 1, `onSlapBottom` → seat 0) instead of one ambiguous shared button. New hook `useLocalBataillecorseDuelGame` (no bot timers, both `submitFlip`/`attemptSlap` driven only by real taps, still runs the shared grace-timeout resolution) and new `BataillecorseDuelTable`/`BataillecorseDuelCenter` components, reusing the vs-bot table's exported pieces (`StockPile`, `PileStack`, `ReactionTimesReadout`, `InfoPanel`, the pile/reaction/fire hooks) rather than duplicating them. Duel matches never call `useRecordMatchResult` - there is no single "you" to attribute a win/loss to.
Context: User asked for a same-phone 1v1 mode for la Bataille Corse where each player sits on their own side of the phone. Two design choices were confirmed with the user up front: the mode lives inside the existing local setup screen (not a new 4th home button), and players are labelled generically "Joueur 1"/"Joueur 2" (no name prompt).
Rationale: The engine (`submitFlip`/`attemptSlap`/`redact`) already takes an explicit `seat` and has no server/bot dependency, so a genuine 2-human mode is a UI/input change, not an engine change - confirmed by reusing it unmodified. Rotating only each player's own corner (not the shared pile) avoids needing a second, mirrored pile renderer; the shared pile is exactly the kind of neutral object every physical card/war-slap game already has in the middle, read from either angle. Splitting the slap hit-target top/bottom was required because a single on-screen button cannot tell which of two simultaneous real taps came from which physical player.
Consequences: `BataillecorseTable.tsx` exports several previously-private pieces (`StockPile`, `PileStack`, `FalseSlapMark`, `ReactionTimesReadout`, `InfoPanel`, and the `useFlash`/`useWinnerFireSeat`/`usePileEnterDirection`/`useDisplayPile`/`useWindowSeenAtRef`/`useSeatReactionMs`/`useSlapWindowUrgent` hooks) for reuse by the new duel table - no behavior change for the existing vs-bot table. `GameSettingsPanel` gained `hideBotFields` (hides the bot-reflex slider in duel mode; deck size stays). New `LOCAL_BATAILLECORSE_DUEL_STORAGE_KEY` so a duel match's local-storage save never collides with a vs-bot one. `npm test` (248/248), `npm run build`, `npm run lint` all pass with the same pre-existing baseline issues as before (`useMatchStats.ts` lint error, unrelated warnings) - no new ones introduced.
