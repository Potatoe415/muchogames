# 0064 — Président: finishing on a 2 forces Trou du Cul at round end

Date: 2026-09-23
Status: Accepted
Decision: A seat that empties its hand by playing a losing 2 (single, pair, or triple - a quad still only toggles revolution, same scope as the existing burn rule) is recorded in a new `GameState.losingFinishSeats: Seat[]` field (`applyPlay`/`losesOnFinish` in `lib/president/play.ts`). Play continues completely normally for the rest of the round - no early end, no change to turn order, pile, or the existing "finishing always beats burn/skip" precedent. Only once the round actually ends does `computeRoundResult` (`lib/president/scoring.ts`) demote every seat in `losingFinishSeats` behind every seat not in it (each group's own relative order preserved) before computing titles and finish-rank points, so a losing-2 finisher becomes Trou du Cul (or the worst rank still available, if more than one seat manages it in the same round) regardless of when it actually emptied its hand. Applies identically solo, online, and ad-hoc, since all three share this one engine.
Context: User asked for the common house rule "finishing on a 2 makes you lose", for both solo and online. Clarified via questions: (1) scope matches the existing burn rule (single/pair/triple, not quad); (2) the round must NOT end early when this happens - it plays out exactly as it would have otherwise; the losing-2 finisher is simply forced into the worst rank once the round's real result is computed, no matter its actual finish position.
Rationale: Encoding this as a deferred, scoring-time demotion (rather than an early round-end or a live re-ranking) keeps `applyPlay`'s turn/pile logic completely untouched and reuses the exact same "seats that emptied their hand" bookkeeping style as `finishedOrder`. It also sidesteps a real wrinkle in the existing engine: only the 1st/2nd/3rd seat to empty its hand ever actually plays a "last card" - the 4th (true last) is auto-assigned Trou du Cul the instant the 3rd empties out, without ever playing anything - so a rule gated on "only if this seat would have been last anyway" would never fire. Demoting at `computeRoundResult` time sidesteps that entirely: it works no matter which of the 3 real finishers (or several, if it happens more than once) triggered it.
Consequences: `games.state` jsonb (Président rows) gains `losingFinishSeats: Seat[]`, reset to `[]` at `createInitialState`/`beginNextRound`. No SQL migration (`state` is opaque jsonb). `finalizeRound`'s cumulative scoring automatically reflects the demoted rank (4 pts for the demoted seat) since it reads `computeRoundResult`'s already-demoted `finishedOrder`. The live in-round "crown" cue (`PresidentTable.tsx`'s `finishedOrder[0]`) is intentionally left alone - it still shows the real first-to-finish seat live, which may later flip to "Trou du Cul" once the round-end score table applies the demotion; this matches the requested behavior (round plays out normally, penalty only lands at the final ranking). Not exposed on `PlayerView`/`redact.ts` - no UI cue was requested, only the ranking rule itself. 8 new unit tests across `play.test.ts` (flagging on single/pair/triple, no flag on quad or non-2 finishes, flag survives the early-round-end branch) and `scoring.test.ts` (demotion, multi-seat demotion order, no-op when unused, `finalizeRound` scoring at the demoted rank); all 262 tests green, `tsc --noEmit`/build clean (pre-existing unrelated `lib/client/useMatchStats.ts:220` lint error untouched, per `docs/BACKLOG.md`).
Alternatives_Rejected: Ending the round immediately the instant the losing 2 lands and ranking the still-active seats by remaining card count (rejected by the user - the round must play out normally); gating the rule on "only if this seat would have been last anyway" (rejected once it was pointed out that no real finisher is ever literally last in this engine's model, so the rule would never be visible); a live re-ranking that flips titles/crowns the moment the losing 2 is played (not requested, adds UI complexity for no asked-for benefit).
