# 0066 — La Bataille Corse: figure/ace sandwich no longer ignores tribute filler

Date: 2026-09-26
Status: Accepted (partially supersedes 0056)
Decision: `detectSlapPattern` (`lib/bataillecorse/pattern.ts`) still runs its filtered figure/ace-only check for the *double* pattern (two same-rank figures/aces with any number of ordinary tribute-attempt cards between them still count as slappable), but no longer runs it for *sandwich*. A sandwich now only ever fires from the real, unfiltered pile - exactly one real card between the two matching cards, whatever that card's rank - never a filtered figure/ace-only "one card" gap that could sit behind an arbitrary number of real filler cards.
Context: User reported a live match where a "sandwich" slap (`Q♥, K♥, 8♥, 7♦, Q♠`) felt inexplicable: the on-screen pile only ever renders its top ~3 cards (separately fixed - see the same-day `PILE_HISTORY_DEPTH` fix), so neither `Q♥` nor `K♥` was ever visible. Investigating, the user then stated the actual rule: "a sandwich only happens with one card in the middle of the sandwich" - i.e. 0056's filtered check was wrong to extend *sandwich* the same way it extends *double*, since 0056's own filtered-sandwich test (`K, 7, Q, K`) has 2 real cards between the outer Kings (`7` and `Q`), not 1, even though only one of them (`Q`) is itself a figure.
Rationale: Reusing `detectOnSequence` unmodified for both patterns on the filtered sequence (0056's original approach) conflated two different ideas: "adjacent" (double, meaningfully skip-tolerant - a run of ordinary tribute attempts between two same-rank figures is still "no other figure came between them") and "exactly one card apart" (sandwich, a specific real-pile distance that stops meaning anything once you're allowed to filter out an unbounded number of real cards from the middle). Splitting `detectOnSequence` into a standalone `detectDouble` for the filtered branch keeps the double behavior 0056 established, drops only the sandwich half.
Consequences: `pattern.ts`'s filtered check now calls `detectDouble`, not `detectOnSequence`. `pattern.test.ts`: the old "figure sandwich across a tribute chain" test now asserts `null`, plus a new test confirming a literal (unfiltered) figure sandwich - exactly one real card between - still fires. `RulesModal.tsx` FR/EN copy updated to say the filler exception applies to the double only. `npm test` (305/305), `npx tsc --noEmit`, `npm run build` pass; `npm run lint` shows only the pre-existing unrelated baseline issue (`useMatchStats.ts`).
Alternatives_Rejected: Requiring the filtered sandwich check to also verify the real-pile gap is exactly 1 (i.e. no filler at all under the sandwich) - equivalent to just removing the filtered check entirely, since a genuinely filler-free gap of 1 is already caught by the unfiltered `detectOnSequence` call; kept the simpler removal instead of a redundant, more complex condition.
