# 0035 — Idle-turn timer: fixed `turn_started_at` not resetting when the same seat leads the next trick

Date: 2026-07-18
Status: Accepted
Decision: `persistGame` (`lib/server/repo.ts`) now always stamps `turn_started_at` to "now" on every call, instead of only when `state.turn` differs from the previous state's turn.
Context: User reported the "are you still there?" popup sometimes appearing almost immediately on their own turn, with only ~5s left instead of the full timeout. Root cause: in both `lib/coinche/trick.ts` and `lib/bouilla/trick.ts`, `applyPlay` sets `turn: winner` when a trick completes - and whoever plays the trick's last card and also wins it (a common, normal occurrence) leads the next trick too, so `state.turn` stays the same seat across that transition. `persistGame`'s old condition (`game.state?.turn !== state.turn`) treated that as "no turn change" and skipped the stamp, so the new trick's clock kept counting from whenever that seat's *previous* turn had started - already partly or fully elapsed - instead of starting fresh for the new decision.
Rationale: Every `persistGame` call already follows an actual move (it is the single choke point every action/idle-timer/takeover path commits through - see the original idle-timer decision above); there is no call site where "a move just happened but the next turn's clock should not restart" is the intended behavior. Seat-equality was never the right signal for "is this a new turn" - a fresh decision point, not a fresh seat, is what should reset the clock.
Consequences: Slightly more writes to `turn_started_at` (every move now bumps it, not just seat changes) - negligible, it's a single column already inside the same `updateVersioned` patch, no extra round trip. No schema change. Full test suite still green (120 tests).
Alternatives_Rejected: Special-casing "trick completed AND winner === last player" in `trick.ts`/`applyPlay` to force a turn no-op vs restart signal - rejected as far more invasive (would leak an online-presence concern into the pure, framework-agnostic rules engines) for the same outcome the one-line `repo.ts` fix already gives for free.
