# 0056 — La Bataille Corse: figure/ace slaps ignore tribute filler, reaction time shown in seconds, online readout merged

Date: 2026-09-17
Status: Accepted
Decision: `detectSlapPattern` (`lib/bataillecorse/pattern.ts`) now also runs its existing double/sandwich test against the pile filtered down to just figure/ace cards, whenever the real top-of-pile card is itself a figure/ace: a Valet or As now counts as slappable against the *previous* same-rank Valet/As even when a seat's own plain tribute-attempt cards (e.g. As, 3, 5, 9, As) sit between them on the real pile - the filler no longer breaks the pattern. The guard (only when the actual top card is a figure/ace) stops an old, already-resolved figure pair from resurfacing once an unrelated plain card is later played on top. Separately: every reaction-time readout switched from raw milliseconds to seconds, 2 decimals (`formatReactionSeconds`, was `formatReactionMs`) - `myReactionTimeLabel`/`opponentReactionTimeLabel` texts changed from "{s} ms" to "{s} s". In online mode only (`selfAvatar !== undefined`, the same signal the self-name label already uses), the two separate per-seat readouts are replaced by one combined "{mine} s / {opponent} s" readout (new `reactionTimesLabel` key) shown in the same spot above the player's own deck, in `--accent-yellow` ("jaune feu") instead of white - sourced from the server-confirmed `PileWinEvent.reactionMsBySeat` for both seats (generalized `useOpponentReactionMs` into `useSeatReactionMs(lastPileWin, seat)`, called once per seat) rather than the local pre-resolution `myReactionMs`, since a false slap has no resolved reaction time to compare against the opponent's. Local/ad-hoc keep the original two-readout layout, just reformatted to seconds.
Context: User-requested rule/UI changes, explicitly walking through the two Valet/As examples that motivated the pattern-detection change (a Valet's single tribute attempt already worked since there's no room for filler; an As's 4 attempts exposed the gap) and specifying the seconds format, decimal count, single merged online location, and "jaune feu" color.
Rationale: Reusing the exact same `detectOnSequence` double/sandwich test on a filtered figure/ace-only sequence (rather than writing bespoke figure-matching logic) kept the change minimal and consistent with the existing "classic double+sandwich only" ruleset scope (2026-09-16 entry) - this is the same two patterns, just with a rank-family-aware definition of "adjacent" for figures/aces, not a new pattern type (no Big Mac/suite/somme-de-10 added). `--accent-yellow` was reused rather than a new CSS variable for "jaune feu" since it is already this app's designated warm-yellow accent (also used for the winning-deck fire glow). `selfAvatar !== undefined` was reused as the online/not-online signal since this file already relies on it for the exact same purpose (gating the self-name label) - no new prop needed.
Consequences: `pattern.ts`/`pattern.test.ts`/`engine.test.ts` gained the filtered check + new test cases (242 tests total, up from 237). `RulesModal.tsx`'s "Les tapes (réflexe)" section (FR/EN) now documents the figure/ace tribute-filler exception. `i18n.tsx` reworded `myReactionTimeLabel`/`opponentReactionTimeLabel` (ms→s) and added `reactionTimesLabel`. `BataillecorseTable.tsx`: `useOpponentReactionMs` renamed/generalized to `useSeatReactionMs`, new `isOnline`/`eventReactionMsMine`/`combinedReactionLabel`, `SeatRow`'s opponent-side readout and the self-side readout are now each gated on `isOnline`. `npm test` (242/242), `npm run build` (Next.js typecheck) pass; `npm run lint` shows only the same pre-existing baseline issues (`useMatchStats.ts` error, `DealOverlay`/`trick.test.ts` warnings), no new ones.
Alternatives_Rejected: A brand-new `SlapPattern` label (e.g. `"figureChain"`) for the filtered-match case - rejected, it still resolves to a plain "double" or "sandwich" and no UI ever displays the pattern label itself, so a third label would only add an unused distinction. Keeping the combined online readout sourced from the local, pre-resolution `myReactionMs` - rejected, it fires even on a false slap (no comparable opponent time yet) and isn't the value the server actually confirmed. Applying the merged single-readout layout to local/ad-hoc too - rejected, the user specified "en mode en ligne" and this app already has an established per-mode signal (`selfAvatar`) for exactly this kind of online-only distinction.
