# 0046 — Home screen becomes a game-picker tile list; each game gets its own splash route

Date: 2026-09-10
Status: Accepted
Decision: `app/page.tsx` ("/") is no longer a game-specific splash with an inline tab switcher (`game` state + `game-tab-*` buttons flipping the whole screen's background/buttons in place) - it is now a plain list of 3 tiles (`game-tile-coinche`/`-bouilla`/`-president`, each a `next/link` to `/coinche`, `/bouilla`, `/president`). New `app/coinche/page.tsx` was added, mirroring the existing `app/bouilla/page.tsx`/`app/president/page.tsx` splash pattern (local/online/ad-hoc buttons + a Rules button/modal, `splashscreen.jpg` background) - Coinche previously had no dedicated splash route because it was simply home's default tab state.
Context: User described the desired flow directly: launching the app shows a list of tiles (one per game), and tapping a tile opens that game's own splash screen - i.e. the tile list and the per-game splash should be two separate screens/routes, not one screen that swaps its content via local state.
Rationale: `/bouilla` and `/president` already existed as exactly this "per-game splash" screen (mode picker + rules), so the only real gap was Coinche never having gotten the same treatment (its content just lived inline in `app/page.tsx`, keyed off `game === "coinche"`, the default). Extracting it into its own route makes all three games symmetric (one splash route each) and turns `app/page.tsx` into a pure, stateless list with no game-specific styling/logic of its own - each individual game's presentation, background, and rules concern stays owned by that game's own splash page (already the pattern for Bouilla/Président), not smuggled into a shared conditional.
Consequences: `app/page.tsx` lost its `GameType`/`showRules` state, `RulesModal`, and the `game-tabs`/`play-*-button` markup (moved verbatim into `app/coinche/page.tsx`, unchanged in behavior). It kept the install-app button and the "Reset browser data" utility button/version label (app-wide concerns, not game-specific). `HomeTopBar`'s external "back to Bergamots hub" link is unchanged and still used on all 4 splash-shaped screens (`/`, `/coinche`, `/bouilla`, `/president`) - tapping it from a per-game splash still exits to Bergamots directly rather than back to this app's own tile list, matching the pre-existing behavior `/bouilla`/`/president` already had (not changed here, out of scope of what was asked). New i18n keys: `chooseGameTitle`/`chooseGameSubtitle` (tile-list heading) and `coincheTileDesc`/`bouillaTileDesc`/`presidentTileDesc` (one-line tile descriptions).
Alternatives_Rejected: Keeping the tab-switcher UI but styling it to look like tiles (would still be one screen with conditional rendering swapping its own background/copy - not what was asked, and keeps Coinche's splash logic entangled with the shared home component instead of living in its own route like the other two games); making `HomeTopBar`'s back arrow route-aware (back to `/` from a per-game splash, back to Bergamots from `/`) - a reasonable follow-up but not requested here, left as-is to keep this change surgical.
