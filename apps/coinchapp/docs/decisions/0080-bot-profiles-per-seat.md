# 0080 — Bot profiles per seat (normal, aggressive, conservative, defensive)

Date: 2026-11-19
Status: Accepted
Decision: Each Coinche/Belote bot seat gets one of four personalities, chosen from a dropdown on that bot (avatar, name, trait bars), default `normal`. Every behaviour difference comes from `BOT_PROFILE_CONFIG` (`lib/coinche/bot-profiles.ts`); decision code never branches on the profile name. Bots now coinche and surcoinche. Supersedes the global punch slider (0012).
Context: Owner wanted distinct bot personalities driven by one engine and one config object, plus avatars per profile.
Rationale: `normal` keeps the calibrated bidding (0009/0011) and the ISMCTS play (0006/0010); other profiles are deltas from it. Bidding: safety margin, distribution weight (short suits weigh `multiplier - 1`, so normal is unchanged), partner trust scales the existing support raise, a trap pass for borderline ambiguous hands. Coinche: a logistic model of "the contract fails" fitted on 21.8k simulated deals (trump points, trump length, side aces/tens, contract level), compared to the profile threshold. Play: ISMCTS stays the brain; `profilePlayBonus` adds a small weighted bias (x0.15) to each root move's win rate, so profiles tip close calls (trump hunt, shortening defence, risk on unguarded tens) without causing blunders. Hard filters from 0017 are unchanged. Calibration (3000 deals, profile team vs normal team; takes / makes / net points per deal): aggressive 81% / 57% / +9.4, conservative 27% / 92% / -50, defensive 37% / 87% / -26 with 53 coinches won 68%, normal 50% / 84% / ~0.
Consequences: `GameSettings.botPunch` is gone (old rows ignored, every bot plays normal); new `GameSettings.botProfiles` (seat -> profile), sanitized server-side. Online: the host sets profiles in the lobby once bots sit (`setBotProfile`, host-only, lobby-only). Local: setup page, passed as `botProfiles=a,n,c` (seats 1-3). Ad-hoc: setup page. A seat converted to a bot by the idle timer plays normal. Belote: only the take threshold varies (no coinche there). The engine-side heuristic card play (`chooseCard`, server fallback) ignores profiles. Avatars live in `public/bots/<profile>.webp` and show on the in-game badge of bot seats.
Alternatives_Rejected: Replacing ISMCTS with a hand-written card scorer (clearly weaker play); hard per-profile filters (would need `if (profile)` branches); keeping punch alongside profiles (two knobs for the same thing); the owner's raw coinche thresholds on a hand-tuned trick count (the simulation showed it was not calibrated: coinches won only 16%).
