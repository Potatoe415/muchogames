# 0048 — Président: the "double" rule - replaying the pile's rank skips the next seat, completing all 4 burns it

Date: 2026-09-11
Status: Accepted
Decision: `isLegalCombo` now also accepts replaying the pile's exact rank (same card count) as an alternative to beating it - always on, no settings toggle. `applyPlay` skips the very next active seat's turn when this happens (`GameState.lastSkip: { seat, skippedSeat, combo } | null`, a display-only cue mirroring `lastBurn`), unless the replay also completes all 4 cards of that rank, in which case it burns the pile instantly like a "2" instead (same seat leads again, reuses `lastBurn`). A new optional `Pile.stackCount` tracks how many cards of the pile's rank are down so far (defaults to `combo?.cards.length ?? 0` when absent, so no existing `Pile` literal needed updating). Finishing your hand on the matching play always takes priority over either effect, same precedent as a hand-emptying "2" never burning.
Context: User's house rule: if someone plays a card (e.g. a 6), the next player may play another 6 on top instead of beating it - this skips the following player's turn. Generalizes to pairs/triples (e.g. a pair of 6s replayed by another pair of 6s). Once all 4 cards of that rank are down this way, the player who completed it "wins the prize": clarified via follow-up questions to mean burning the pile immediately (same mechanic as a "2"), always on (no settings toggle), applying to every combo size 1-3.
Rationale: Reusing the existing `lastBurn`/burn-animation plumbing for the "completes to 4" case avoids new UI work and keeps the two "unbeatable, pile clears, same seat leads" cases visually consistent. `stackCount` as an optional field (rather than required) meant only `play.ts`/`combos.ts` needed changes - every pre-existing `{ combo: null, leader: null }`/`{ combo, leader }` literal across `deal.ts`/`exchange.ts`/test files kept working unchanged.
Consequences: Président `games.state` jsonb now includes `lastSkip` (null after deal / next round / end of exchange, same clearing points as `lastBurn`) and `pile.stackCount` (optional). New `SkipFlash` component (`PresidentTable.tsx`) reuses the `.belote-flash` CSS animation for a centered "Tour sauté : {player} !" banner, diffed the same way `usePileDisplay` detects a new burn. `presidentEngineAdapter.ts`'s bot-loop pause (`didCollectTrick`) now also triggers on a new `lastSkip`, matching the existing burn/hand-empty pause. Rules modal text updated (both languages) with a new "Le doublé"/"The double" section. No SQL migration (`state` is opaque jsonb).
Alternatives_Rejected: Making it a settings toggle (user explicitly wants it always on); a distinct "prize" animation/field separate from the existing burn cue (user confirmed the mechanic is identical to a "2" burn, so reusing it is simpler and consistent); requiring `Pile.stackCount` instead of leaving it optional (would have forced touching every existing pile literal across the engine and its tests for no behavioral gain).
