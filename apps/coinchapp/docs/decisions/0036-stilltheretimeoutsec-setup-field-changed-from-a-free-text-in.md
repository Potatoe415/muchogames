# 0036 — `stillThereTimeoutSec` setup field changed from a free-text input to a discrete slider (10/15/20/30/60)

Date: 2026-07-18
Status: Accepted
Decision: Superseded this same day's earlier "make the text field clearable" fix - `GameSettingsPanel.tsx`'s timeout field is now a `type="range"` slider (same pattern as `botPunch`'s), snapping to one of `STILL_THERE_TIMEOUT_OPTIONS` (new shared const in `lib/supabase/types.ts`: `[10, 15, 20, 30, 60]`). `stillThereTimeoutSec` is back to a plain `number` in `GameSetupValues`. `lib/server/actions-lobby.ts`'s `sanitizeStillThereTimeoutSec` now imports the same list instead of keeping its own separate copy (which was also missing the new `60` option).
Context: User request to replace the text field with a slider outright, rather than continue fixing free-text edge cases.
Rationale: A slider limited to the server's already-enforced discrete option list (`sanitizeStillThereTimeoutSec` only ever accepted 10/15/20/30, defaulting silently to 15 otherwise) removes the "clearable text field" class of bug entirely instead of patching around it, and matches the existing `botPunch` slider UX already in this same panel. Sharing one options list between the client slider and the server sanitizer (previously two separately-hand-maintained arrays, out of sync once `60` was added) prevents them drifting again.
Consequences: `components/GameSettingsPanel.tsx`'s earlier same-day change (string-typed field, parsed on submit) is fully reverted/replaced by this one. `app/online/page.tsx`'s submit handler passes `setup.stillThereTimeoutSec` straight through again (no `Number(...) || 15` needed - the slider can only ever produce a value already in the list). Typecheck clean, full suite still green (120 tests).
Alternatives_Rejected: Keeping the free-text field and only fixing its edge cases (already attempted this same day, but the user asked for a slider instead once they saw the fix - simpler UX with no way to enter an invalid value in the first place).
