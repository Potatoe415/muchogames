# 0051 — Fourth game "la Bataille Corse": local-reaction-time slap resolution, 2-player seat count generalized

Date: 2026-09-16
Status: Accepted
Decision: Added a fourth game, la Bataille Corse (2 players only), reusing the same three-mode architecture (local/online/ad-hoc) as Coinche/Bouilla/Président. Its signature reflex mechanic ("first to slap the pile wins it") is resolved online by comparing each side's own **locally measured** reaction time (`SlapClaim.reactionMs` - elapsed ms on that seat's own client from when it rendered the open slap window to when it tapped) - never network arrival order or server receipt time. A window collects claims for up to `SLAP_GRACE_MS` (3000ms); once both seats have claimed, the lower `reactionMs` wins regardless of which claim's HTTP request happened to land first. Ruleset scope (per explicit user sign-off): the "classic" slap patterns only (double + sandwich, not Big Mac/suite/somme-de-10), a false-slap penalty of 1 card slid face-down under the pile, and the full Jack/Queen/King/Ace tribute-challenge system (1/2/3/4 attempts), since tributes are what actually distinguish "Bataille Corse" from plain "Bataille". Since this is the first non-4-seat game, `seatCountFor(gameType)` was introduced and threaded through every previously-hardcoded `[0,1,2,3]`/`4` in the lobby/bot-fill/start-game/bot-seat-picker code (see docs/DATA_MODEL.md's 2026-09-16 entry for the full list).
Context: User asked for the new game, explicitly delegating rules research ("je te laisse aller chercher les règles sur internet") but specifying the reflex/no-network-timing requirement as the one hard constraint, and confirming ruleset scope, false-slap penalty, slug name ("bataillecorse"), and doc-update permission via an upfront clarifying round of questions given the size of the change.
Rationale: A "collect claims for a bounded grace window, then compare only the self-reported values" design was the simplest way to honor "never use network time" while still working within this project's existing request/response Server Actions model (no persistent per-game socket/loop) - a truly instantaneous push-based race arbiter would need a different realtime transport than every other game already uses, out of proportion to what was asked. The grace window is generous enough that in normal conditions both a real human's and a bot's claims are always collected before resolution, so the comparison is in practice always decided by `reactionMs`, not network luck. The existing "host runs bot seats client-side" trust model (docs/TECH.md) already accepts a host being able to see/influence outcomes it shouldn't in principle be trusted with (ad-hoc P2P, bot hands) - self-reported reaction time carries the same accepted trade-off (a malicious client could in principle lie about its own `reactionMs`), not a new one.
Consequences: New `lib/bataillecorse` pure rules engine (types/cards/deal/pattern/tribute/engine/bot/redact, 32 tests). The shared turn-based idle-timer/stale-turn machinery (`isActivePhase`, `chooseHeuristicMove`, `HeuristicMove`/`BotMove` unions) gained a `flip` case; a slap is deliberately *not* turn-gated (`submitBotMove`'s `not_bot_turn` check is skipped for `slap` moves) since either seat may attempt one at any time a window is open. New `lib/server/slap-timer.ts` (`advanceStaleSlapWindow`, online only) mirrors the idle-turn/round-gate timers' `getView`-polled pattern; local/ad-hoc instead schedule the same grace resolution via a plain `setTimeout`, since neither has a polled `getView` loop. Found and fixed a real latent bug while wiring the online bot runner: `lib/client/useBotRunner.ts` defaulted any non-"bouilla" game type to the Coinche ISMCTS brain regardless of the view shape it was actually given - silently wrong-but-untested for every other non-Bouilla game until "bataillecorse"'s differently-shaped view crashed it at runtime; now explicitly excludes `"bataillecorse"` (Président's own exposure to the same latent bug was left alone and flagged in BACKLOG, since fixing it wasn't requested and risks an untested regression). No custom splash art generated for `/bataillecorse` (plain felt background instead), since the user did not explicitly ask for image generation.
Alternatives_Rejected: Comparing raw server-receipt order of two `attemptSlap` calls (rejected - exactly the "network time" the user said not to use). A richer slap ruleset (Big Mac/suite/somme-de-10) - user picked the classic double+sandwich set when asked. A 3-card false-slap penalty - user picked 1 card. Waiting indefinitely for a second claim with no grace timeout (would let one absent/slow player freeze the pile forever - every other timer in this codebase is opportunistically polled from `getView`, so this follows the same convention). Reusing the generic turn-based `runBotLoop`/`useLocalCardGame` abstraction for local/ad-hoc (rejected - a slap race is fundamentally not a "whoever's turn it is decides" loop; forcing it in would have made the abstraction leakier for every other game too, so a bespoke hook was simpler and safer).
