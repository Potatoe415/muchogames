# 0008 — Add a password-protected admin stats page, backed by a new Supabase events table

Date: 2026-08-30
Status: Accepted
Decision: Added `/admin/index.html` (a static page under `public/admin/`) showing the ranking of games launched from the hub. Launches are recorded by a new public `POST /api/track` into a new Supabase table `muchogames_events`, and aggregated by `POST /api/admin/stats`, which gates access by comparing the posted password to the `ADMIN_PASSWORD` env var server-side. Traffic is instrumented at a single point: a click listener on each hub tile in `hub.js`, calling `trackGameLaunch` from the new `shared/js/analytics.js` via `navigator.sendBeacon`.
Context: User asked for an admin space and, after being shown the options, scoped it down to "just the ranking of launched games for now", with two hard requirements: it must be free, and it must be ultra simple, explicitly accepting weak security. User also specified the table name must be `muchogames_events`, as part of a progressive rename from "bergamots" to "muchogames".
Rationale: Reuses infrastructure that already exists and costs nothing (the shared `multigames-db` Supabase project, Vercel Hobby functions, `@supabase/supabase-js`), so no new vendor, dependency, or bill. Vercel's built-in Password Protection was rejected because it requires a paid plan. A client-side password check was rejected because it would be readable in the page source and protect nothing, while a server-side check against an env var is the same amount of code and actually works. Instrumenting only the hub tiles (rather than each of the 15 games) captures 100% of launches, since every game is started from the hub: two lines in `hub.js` instead of touching 15 game folders.
Consequences: New required env var `ADMIN_PASSWORD` on Vercel; `supabase/migrations/0002_events.sql` must be run manually before the page works. `POST /api/track` is public and unauthenticated, so anyone who finds the URL can inflate the counters. `muchogames_events` is append-only with no TTL or purge job, making it the first long-lived persisted data in a project whose stated persistence model was "ephemeral only"; `docs/PRODUCT.md` and `docs/TECH.md` were updated with user approval to drop the "no authentication" and "Supabase is only for Yatzy" claims. Visitors who block JavaScript are not counted, and `api/admin/stats.js` caps reads at 10000 rows. Stats are unavailable under `npm run dev` (Vite does not run `api/*`); `vercel dev` is required locally.
Alternatives_Rejected: Storing stats in Vercel Web Analytics - rejected because the data is only visible in Vercel's own dashboard, not on a self-hosted password-protected page, and custom events need a paid plan. Writing the counters into a committed JSON file via the GitHub API - rejected as far more moving parts for the same result. Adding a real auth provider (Supabase Auth, Clerk) - rejected as vastly disproportionate for a single-user stats page, and against the project's no-accounts stance. Building the wider admin surface first proposed (wordpack editor, hub tile management, content validator) - deferred by the user to keep this change small.
