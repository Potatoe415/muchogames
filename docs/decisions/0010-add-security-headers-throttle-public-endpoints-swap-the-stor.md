# 0010 — Add security headers, throttle public endpoints, swap the stored admin password for a signed token

Date: 2026-08-30
Status: Accepted
Decision: Added `vercel.json` carrying security headers (global `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options: SAMEORIGIN`, `Permissions-Policy`; `Cache-Control: no-store` on `/api/*`; a strict Content-Security-Policy on `/admin` only). Split admin auth into a new `POST /api/admin/login` that verifies the password with `crypto.timingSafeEqual` and returns a 1h HMAC-signed token; `POST /api/admin/stats` now accepts only that token. Added `api/_lib/rateLimit.js`, an in-memory throttle applied to login (10 attempts / 10 min / IP) and to `/api/track` (60 events / min / IP). Added `ADMIN_PASSWORD` to `.env.example`.
Context: Audit priority 2 (see the audit action plan in `docs/BACKLOG.md`). The project had no `vercel.json` at all, so zero security headers; the admin password was brute-forceable without limit, compared with `!==`, and stored in plaintext in `sessionStorage` where any XSS could read it; `/api/track` was an unbounded write path into the Supabase project shared with coinchapp. The user confirmed traffic is currently very low.
Rationale: The token is signed with `ADMIN_PASSWORD` itself as the HMAC key and carries its own expiry, so verification stays stateless - no session table, nothing to keep in sync - and rotating the password automatically invalidates live sessions. The throttle is deliberately in-memory rather than Redis/Upstash: at very low traffic, a shared store would mean a new vendor and a new bill to defend a hub of party games, whereas per-instance counters already make a brute-force burst expensive. CSP was scoped to `/admin` rather than applied site-wide because the games pull from `esm.sh`, Google Fonts and Supabase over websockets, so a global policy needs per-game verification; `/admin` is small, fully controlled, and was verified under the real policy (fonts, inline style attribute for the ranking bar, same-origin fetch, module execution).
Consequences: `ADMIN_PASSWORD` must now be treated as a signing key, not just a password: changing it logs the admin out. Admin sessions expire after 1h. `X-Frame-Options` is `SAMEORIGIN`, not `DENY`, because `public/games/cafards/index.html` displays its rules in a same-origin iframe - `DENY` would break that modal. The throttle resets on serverless cold start and is not shared across concurrent instances, so it is a cost-raiser, not a guarantee. `/api/*` responses are now `no-store`, which also removes the risk of the Yatzy service worker caching a game-state read.
Alternatives_Rejected: Upstash Redis / Vercel KV for a correct distributed rate limit - rejected as disproportionate at current traffic, and it introduces a paid dependency; noted as the upgrade path if abuse appears. A site-wide CSP - deferred, it needs each of the 10 games verified individually. Vercel's built-in Password Protection - still paid-plan only. An httpOnly session cookie instead of a token in `sessionStorage` - rejected for now as it needs CSRF handling that a token in a request body does not, for the same practical protection on a single-user page.
