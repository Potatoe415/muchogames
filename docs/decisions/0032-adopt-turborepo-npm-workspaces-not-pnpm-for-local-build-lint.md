# 0032 — Adopt Turborepo (npm workspaces, not pnpm) for local build/lint orchestration

Date: 2026-09-17
Status: Accepted
Decision: Added `turbo.json` and `package.json`'s `"workspaces": ["apps/coinchapp"]` so `npm run build:all` / `lint:all` (→ `turbo run build` / `turbo run lint`) orchestrate the hub (root, via the `//#build`/`//#lint` root-task syntax) and `apps/coinchapp` together, with local task caching (a repeat build/lint of an unchanged package is a cache hit). `apps/tranquil` is **not** a workspace member and is not in the Turborepo graph.
Context: User asked, after the `coinchapp`/`tranquil` colocation and mid-Vercel-repoint, for "the most maintainable, modular, clean, recent (Sept 2026)" architecture, having reconsidered whether to unify everything into one framework. Agent pushed back on full unification (rewriting two live real-time multiplayer apps, or 17 vanilla-JS games, for zero player-facing benefit) and instead recommended adopting Turborepo — Vercel's own monorepo orchestration tool — as the actual current (Sept 2026) best practice for a multi-framework monorepo, while keeping each app's existing framework. User said to proceed.
Rationale: The agent's initial framing (a few messages earlier) paired Turborepo with pnpm as "the modern combo" — reconsidered once actually implementing: `apps/tranquil` already declares its own nested npm workspaces (`"workspaces": ["shared", "client"]`), and npm workspaces cannot nest inside another workspace (npm has no recursive-workspace support). Migrating everything to pnpm now — mid-way through `coinchapp`'s live Vercel repoint, and while `tranquil`'s nesting issue would still need solving one way or another — added migration risk (three different lockfiles to convert, Vercel's build-tool auto-detection depends on which lockfile is present) for marginal benefit over just using Turborepo with npm workspaces, which already delivers the two things actually asked for: task caching and one shared orchestration layer. `apps/coinchapp` has no nested workspace, so it was safely added as a real workspace member (`npm install` confirmed clean hoisting, no `package-lock.json` conflicts — Vercel's build of `coinchapp-monorepo` reads only `apps/coinchapp`'s own lockfile via its Root Directory setting, so this root-level change cannot affect that deployment). `apps/tranquil` was excluded rather than restructured (e.g., flattening its `shared`/`client` up to become direct root workspace members) because that would change `tranquil`'s own internal layout — a separate decision belonging to that app, not something to force as a side effect of this repo's tooling choice. Turborepo needed an explicit `packageManager` field (`npm@11.14.0`) and the `//#build`/`//#lint` syntax to include the root package's own scripts — neither run by default, discovered by testing rather than assumed.
Consequences: `npm run build`/`lint`/`format`/`check` (unprefixed, root-only) are unchanged; `build:all`/`lint:all` are new, additive, turbo-orchestrated. `.turbo/` added to `.gitignore`. Running `lint:all` surfaced one pre-existing lint **error** inside `apps/coinchapp` (`react-hooks/set-state-in-effect` in `lib/client/useMatchStats.ts`) that root `npm run lint` never saw (it excludes `apps/**`) — flagged in `docs/BACKLOG.md`, not fixed, since it's `coinchapp`'s own pre-existing app code, governed by `apps/coinchapp`'s own `AGENTS.md`, not this repo's. `apps/tranquil` stays fully self-managed (`cd apps/tranquil && npm run build:shared && npm run build -w client`), unaffected by any of this — verified building standalone after the change. No `packages/` shared-code extraction was done in this pass (still copy-pasted/duplicated where it exists) — that remains a future, incremental step once real duplication pain shows up, per YAGNI.
Alternatives_Rejected: pnpm workspaces — rejected for now due to `tranquil`'s nested-workspace conflict and mid-migration timing risk; revisit once `tranquil`'s internal structure is decided separately. Forcing `apps/tranquil` into the root workspace by flattening its internal `shared`/`client` folders up a level — rejected, that changes `tranquil`'s own layout as a side effect of an unrelated tooling decision. Nx instead of Turborepo — rejected, heavier/more enterprise-oriented than needed for a solo-maintained repo already on Vercel, where Turborepo is the native, lighter-weight fit.
