# 0027 — Split `yatsy/app.js` rendering and online-sync/session blocks into `render.js`/`session.js`

Date: 2026-09-09
Status: Accepted
Decision: Extracted `public/games/yatsy/render.js` (`window.YATZY_RENDER.createRenderer(deps)`, `render()` and every `build*`/`create*`/`render*` DOM helper it calls) and `public/games/yatsy/session.js` (`window.YATZY_SESSION.createSessionController(deps)`, matchmaking wiring, session persistence, remote-state sync) out of `app.js` (2204 → 1187 lines). Both are factory functions called once from `app.js`, each returning the handful of functions `app.js` still needs to call (`{ render }`; `{ handlePlayOnline, handleCreateGame, ..., leaveCurrentGame, syncOnlineGameState, clearPersistedOnlineSession }`). `app.js` immediately aliases those returns to `const` bindings with the original names (e.g. `const render = renderer.render;`), so every pre-existing call site keeps working unchanged instead of being rewritten to `renderer.render()` / `session.syncOnlineGameState()` throughout the file.
Context: Direct follow-up user request ("Yatzy: découper le bloc rendu et le bloc session/sync") to continue the split flagged as the next step in the 2026-09-09 storage.js decision above.
Rationale: Both blocks read the live `state`/`elements` objects and call back into `app.js`'s core game-logic functions (scoring, turn predicates, robot/defeat-mode resets), so a clean split needed an explicit `deps` object per factory rather than a mechanical cut, exactly as flagged in `docs/BACKLOG.md`. Two categories of shared mutable data needed special handling: `CATEGORIES`/`UPPER_CATEGORIES`/`LOWER_CATEGORIES` are full-array *reassignments* on every rule-settings change (`initializeRuntimeDefinitions`), so `render.js`/`session.js` receive getters (`getUpperCategories: () => UPPER_CATEGORIES`, etc.) instead of a snapshot value; `scoringAnimationInFlight` is flipped by both the local scoring flow (stays in `app.js`) and the remote-sync flow (moved to `session.js`), so it stays a single `let` in `app.js` with a getter/setter pair threaded into both `render.js` and `session.js`. Functions used by both online and local/robot/defeat-mode flows (`isOnlineGame`, `resetGame`, `maybeTriggerOnlineYatzyCelebration`'s shared celebration timer, the emoji/defeat-mode notice handlers) stayed in `app.js` and were passed into `session.js` as deps, rather than moved, to avoid duplicating or fragmenting state that many callers share. `remoteSyncPromise`/`pendingRemoteSyncCount`/`remoteApplyInFlight` had no callers left in `app.js` after the move, so they became private `let`s inside `session.js`'s factory closure. A handful of `addEventListener` calls (create/join/share/cancel/play-online/splash-back/join-code-input) were wired *before* the point in the script where `session.js`'s returned handlers get aliased, so those specific listeners were wrapped in a one-line arrow function (`() => handleCreateGame()`) to defer the lookup to click time instead of capturing an undefined reference at wiring time.
Consequences: `public/games/yatsy/index.html` gained `<script src="render.js">` and `<script src="session.js">`, both loaded before `app.js`. `app.js` is now 1187 lines (from 2204) and holds only the core game engine (dice/turn/scoring state, robot AI, defeat mode, the DOM-flight scoring animation shared by local and remote scoring) — still over the 300-line limit, tracked as its own follow-up in `docs/BACKLOG.md` Later, since that remainder is one cohesive concern rather than an obvious layer to peel off. Verified live in the browser: solo + 2-player local games (roll, lock/unlock dice, score, turn pass), a settings-panel rule toggle that rebuilds `CATEGORIES` mid-session (the main correctness risk of the getter approach — confirmed the newly-enabled category appeared in the scoreboard), emoji reactions, and the online create/join flow failing gracefully with the expected connection-error message (no Supabase configured in local dev). `npm run lint`/`format:check`/`build` all pass; lint warnings unchanged at 13 (same pre-existing warnings, some now reported from their new file).
Alternatives_Rejected: Rewriting every internal call site to `renderer.render()` / `session.xxx()` instead of aliasing — rejected as far riskier for a mechanical, high-volume find/replace (dozens of `render();` call sites) with no test suite to catch a missed spot. Moving `maybeTriggerOnlineYatzyCelebration` and the emoji/defeat-mode notice handlers into `session.js` since they are matchmaking-callback-adjacent — rejected, they share mutable state/timers with their local-mode siblings that stayed in `app.js`, so moving them would have split a single timer's writers across two files instead of keeping one owner.
