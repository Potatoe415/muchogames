# 0028 — Deduplicate `engine.js`; add `shared/CONTRACT.md`

Date: 2026-09-17
Status: Accepted
Decision: Deleted the root `shared/js/engine.js` copy; `public/shared/js/engine.js` is now the single source, imported by `wordplayer.js` via a relative disk path (`./public/shared/js/engine.js`). Added `shared/CONTRACT.md`, a short doc listing the public API of every shared module (`engine.js`, `analytics.js`, `player-profile.js`, `game-header.js`) so a future game (or an LLM building one) can read a few hundred tokens instead of the source files.
Context: User read an article proposing a full pnpm/Turborepo/Nx monorepo (`/apps` + `/packages`) ahead of a planned refonte, anticipating many more games (V2 also folding in the external `coinchapp`/`tranquil` repos). Assessed against this project's actual stack (vanilla JS, no bundler for any game except `wordplayer.js`/`hub.js`, no TypeScript) and found the tooling disproportionate — most games have no import graph for a workspace protocol to help with. User confirmed: keep V1 scoped to this repo only, and take the two ideas worth keeping now (kill the one real duplication; document the shared "core" for the LLM) without the heavier tooling.
Rationale: This reverses the 2026-08-30 "deliberately left as-is" call in `docs/BACKLOG.md`, which had assumed consolidating would require pointing `wordplayer.js` at the `public/` copy — true — but did not verify whether Vite's dev-time restriction on importing from `publicDir` (which applies to root-absolute URL imports like `/foo.js`) would block a same-repo *relative* import (`./public/shared/js/engine.js`). Tested directly: `npm run build` and `npm run dev` both work, and the bundled output (`wordplayer-*.js`) is byte-identical before/after, since Vite resolves relative imports by disk path regardless of whether that path happens to sit under `publicDir` — the restriction only fires for URL-style imports. `public/shared/js/engine.js` was kept (not the root copy) because it is the only one reachable at runtime by the unbundled games (`pictionary`, `olemains`) that load it via a plain `<script>`-relative import; the root file could never be served in production once `wordplayer.js` stops needing its own copy.
Consequences: `shared/js/` (root) now holds only `analytics.js`. `wordplayer.js`'s import path changed; no other call site did (`pictionary`/`olemains` already pointed at the `public/` copy). `shared/CONTRACT.md` is the new canonical description of `shared/`'s public API — update it whenever a shared module's signature changes, per the DRY rule in `AGENTS.md`. Verified live in the browser (`npm run dev`, Pictionary via `wordplayer.html?game=pictionary`): options panel rules text loads (`loadRulesIfExists`), "Démarrer" pulls and renders a word with its category color (`loadGameData`/`pullRandomWord`/`renderWordToScreen`/`applyCategoryColorToElement`). `npm run check` (lint/format/build) passes, lint warnings unchanged at 13 (pre-existing, untouched per `AGENTS.md`).
Alternatives_Rejected: Full pnpm/Turborepo/Nx monorepo restructuring now — rejected as premature (YAGNI): no bundler runs on ~15 of the ~17 games, no TypeScript for the article's `.d.ts`-based token savings, and the pain it targets (cross-origin duplication with `coinchapp`/`tranquil`) is explicitly deferred to V2. Keeping both `engine.js` copies "in sync by hand" — rejected, that is exactly the drift risk the 2026-08-30 entry already flagged as a known issue.
