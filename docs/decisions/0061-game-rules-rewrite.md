# 0061 — Game rules rewrite: Game Dashboard, solo best, 40px bottom margin, tested boilerplate

Date: 2026-11-05
Status: Accepted
Decision: `docs/PLATFORM_RULES.md`, `docs/NEW_GAME.md` and `AGENTS.md` are replaced by the owner's 2026-11-05 drafts, corrected against the shared code. New games (added after this decision; Piou, added the same morning, counts as existing) open on a Game Dashboard (best score, Resume above New game), show a live score and keep a separate best (`muchogames_<id>_best`) when solo performance is measurable, save under `muchogames_<id>_save`, and keep an unconditional 40px bottom / 24px side margin. `docs/NEW_GAME.md` ships a five-file boilerplate that passes `scripts/check-games.mjs`. Existing games are brought to the new rules one by one and keep their current `localStorage` keys. The draft's intellectual-property rule is dropped.
Context: The owner wanted one set of rules for new and old games. The drafts' boilerplate did not match the shared code: an invented header (no `game-options-button` / `game-options-panel`, so `npm run check` failed), `initOptionsPanel()` without arguments (no panel), no click handler on the ✖ (`game-session.js` re-clicks it after the dialog), a `100dvh` shell under an in-flow header with `overflow: hidden` (bottom 60px clipped), `rem`-capped text (1.7% of a 4K screen), no `data-tv-back`, unvalidated `localStorage`.
Rationale: The rules keep the drafts' structure and intent; the boilerplate was extracted verbatim from the doc into a scratch game and checked: `check-games` OK, prettier OK, options panel with "Report a problem", ✖ → dialog → dashboard with Resume, resume, end screen and best, an invalid save dropped, no scroll at 360×640, 640×360, 960×540, 1920×1080 and 3840×2160 (text 2.4% and controls ≥ 5.5% of the height, header 3% from the edges), TV Back → ✖ dialog, focus on Resume then arrows to New game. Every `[verified: <rule>]` marker names the rule `check-games.mjs` prints. Renaming existing keys would wipe players' saves and records.
Consequences: PLATFORM_RULES sections are renumbered (TV is 7, resume is 5); references in `shared/CONTRACT.md`, `tv-remote.js`, `docs/BACKLOG.md`, `docs/DATA_MODEL.md`, `yatsy/resume.js` and two `NOTES.md` follow. The thumbnail rule now says square crop (`hub-home.css`, decision 0058), not 4:5. "Never hide overflow on the page" stays. `finish({ score })` without `won` still forwards nothing to the shared profile (backlog).
Alternatives_Rejected: Applying the drafts verbatim (every new game would fail `npm run check` and lose its options panel). Migrating every existing game now (large multi-game change, owner chose one by one). Keeping an intellectual-property rule with a list of exceptions (owner dropped the rule).
