# 0036 — Add a wins/losses counter to Yatzy, kept client-only and per-app (not synced to coinchapp/tranquil)

Date: 2026-09-17
Status: Accepted
Decision: `public/shared/js/player-profile.js` gained `getWins()` / `getLosses()` / `recordGameResult(won)`, backed by a new `bergamots-game-results` `localStorage` key, read on `/profile` (`profile-stats.js`, next to the existing launch-count stats). Yatzy (`app.js`/`session.js`) calls `recordGameResult` exactly once per finished game, but only in "robot" (vs bot) and "online" modes, where there is an unambiguous local player; the same-device 2-player "solo" mode (misleadingly named — see `index.html`'s splash buttons) is skipped, since both players share this browser. `coinchapp` (Coinche/Bouilla/Président/Bataille Corse) and `tranquil` got their own **separate**, app-local win/loss counters instead of feeding this same key — see their own `docs/DECISIONS.md` entries.
Context: User asked to confirm the existing profile-name-sharing setup was still intact across every card game, then asked to add a wins/losses stat to all of them, including Yatzy ("le Yam"). Investigation found: name-sharing is indeed still intact (verified in code, not just docs — `hub.js` `appendLaunchParams()` → `?name=` → `coinchapp`'s `hubName.ts` / `tranquil`'s `hubAvatar.ts`; Yatzy reads `PlayerProfile` directly, same origin); the "authentication" the user recalled is `auth.js`'s client-only Google status widget (no verified identity, no server record); and no win/loss stat existed anywhere yet — `docs/PRODUCT.md`'s Out_Of_Scope explicitly listed "Persistent scores/progress across sessions". User confirmed (via explicit question, not silently assumed): keep everything client-only/per-browser (no real accounts), let each cross-origin app show its own stats in its own UI rather than trying to sync back to the hub's `/profile`, and use one combined counter per app rather than one per individual game.
Rationale: `coinchapp` and `tranquil` are on different origins (`coinchapp.vercel.app`, `tranquil-woad.vercel.app`) from the hub and cannot reach its `localStorage` — the existing architecture only ever pushes data one way (hub → game, via `?name=`/`?avatar=` launch params), never back. Extending that one-way channel to also carry results back, or standing up a real account system so stats could live in one place, were both rejected as disproportionate for a stat display (see the user's explicit choice below). Yatzy already shares its origin with the hub, so its counter naturally lives in the same `PlayerProfile` module as the name/avatar/launch stats it already exposes, no new transport needed. The `localResultRecorded` module-level flag (reset in `resetGame()`) guards against double-counting, since `hydrateFromRemoteGameState()` (remote sync) and `finishGame()` (local turn completion) can each independently observe `gameOver` becoming true for the two different online seats.
Consequences: `docs/PRODUCT.md`'s Out_Of_Scope line about "Persistent scores/progress across sessions" is now inaccurate for this one stat and needs a user-confirmed edit (not done in this same commit — `docs/PRODUCT.md` requires explicit confirmation before every edit, asked separately). A player who clears site data, or who plays via `npm run dev` on a fresh browser, starts back at 0/0, same as the pre-existing launch-count stats. Draws are not counted as a win or a loss. `shared/CONTRACT.md` updated.
Alternatives_Rejected: A real per-player account (Supabase Auth or similar) so stats follow the player across devices/apps — rejected by the user as disproportionate infra for a stat display, and it would have contradicted the project's long-standing "no accounts" stance without a much bigger, separately-scoped decision. Funnelling `coinchapp`/`tranquil`'s results back into the hub's own counter (e.g. via a `?result=` param on the "back to hub" link) — rejected by the user in favor of each app showing its own stats locally; also would have been lossy (never fires if the player just closes the tab instead of clicking back). One counter per individual game (Coinche vs Bouilla vs Président vs Bataille Corse counted separately) — rejected by the user in favor of one combined counter per app.
