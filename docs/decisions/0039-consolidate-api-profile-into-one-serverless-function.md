# 0039 — Consolidate `/api/profile/*` into one Serverless Function

Date: 2026-09-25
Status: Accepted
Decision: Merge the 5 `api/profile/*` endpoints (`get`, `upsert`, `add-results`, `launch-code`, `record-result`) into one function, `api/profile/index.js` (route `POST /api/profile`), dispatching on a new `action` field in the JSON body.
Context: Every production deploy since (at least) commit `c6f602d` failed with Vercel's `exceeded_serverless_functions_per_deployment` — the Hobby plan caps a deployment at 12 Serverless Functions, and `api/` had grown to 14. Production was silently stuck on an older successful build while every later push, including an unrelated hub home-page change, never went live.
Rationale: Consolidating same-topic endpoints into one action-routed function is reversible, has no cost, and only touches this hub's own client code — grepping confirmed coinchapp/Tranquil never call `/api/profile/*` directly (they use `muchogames_launch_codes` against their own Supabase client instead). Drops the function count from 14 to 10, leaving headroom before hitting 12 again.
Consequences: `/api/profile/get`, `/upsert`, `/add-results`, `/launch-code`, `/record-result` no longer exist; every caller now POSTs `/api/profile` with `{ action: "...", ... }`. Per-action rate-limit configs were preserved exactly (same `maxHits`/`windowMs`, keyed as `profile-<action>:<clientKey>`). `docs/tasks/unified-profile-accounts.md` (a historical planning note, not live route documentation) still mentions the old per-action paths and was left as-is.
Alternatives_Rejected: Upgrading the Vercel project to Pro (removes the 12-function cap entirely) — rejected for now since it adds a recurring cost for a limit this repo can stay under by consolidating; can revisit if the function count grows again. Consolidating `api/yatsy/games/*` instead — rejected as the first move since `/api/profile/*` was the larger, more homogeneous group (5 endpoints, identical auth pattern) and gave enough headroom on its own.
