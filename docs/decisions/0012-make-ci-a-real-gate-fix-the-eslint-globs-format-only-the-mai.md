# 0012 — Make CI a real gate: fix the ESLint globs, format only the maintained surface

Date: 2026-08-30
Status: Accepted
Decision: Repointed `eslint.config.mjs` at the real tree (`public/**`, repo root, `shared/**`, plus a service-worker block and a `sourceType: "script"` block for `diceduel`), so `npm run lint` went from 1207 errors to 0 errors and 16 warnings. Added `.prettierignore` excluding build output, game content data, Markdown, and - deliberately - all of `public/games/**`. Added `endOfLine: "auto"` to `.prettierrc`. Ran `prettier --write` on what remains: 52 files, all of them the actively maintained surface (`api/`, `shared/`, `public/shared/`, `public/admin/`, the hub, the configs, the rules fragments). Switched CI from `npm install` to `npm ci`. `npm run check` now exits 0 end to end for the first time.
Context: Audit priority 4. CI ran lint, then `format:check`, then build, and had been red since it was written, so the build step had almost certainly never executed. Two root causes, both mis-diagnosed in the audit itself. First, the browser-globals block targeted `apps/**`, a directory that does not exist, leaving every game file with no globals: 1164 of the 1217 messages were phantom `no-undef` on `document` and `window`. Second, the audit blamed a quote mismatch, but measurement disproved it - switching to `singleQuote` changed the churn by less than 3% (18,584 lines versus 18,075). The code had simply never been run through Prettier. Separately, `core.autocrlf=true` with no `.gitattributes` means the Windows working tree is entirely CRLF, so Prettier's default `endOfLine: "lf"` flagged every line of every file locally, inflating the apparent damage.
Rationale: Formatting everything would have been 101 files and roughly 20,000 changed lines across 10 games that have no tests, burying every real diff. Formatting nothing would leave the gate red forever. The ratchet - ignore `public/games/**`, remove a game from the list the next time someone works on it - makes the gate real today for the code actually being changed, at zero risk, and shrinks the debt monotonically. Game content data (question banks, wordpacks) is excluded permanently: reformatting it produced ~500,000 changed lines for no readability gain. Markdown is excluded because `docs/DECISIONS.md` is append-only and Prettier's table realignment would rewrite past entries. `endOfLine: "auto"` fixes the tool on Windows without rewriting the tree, which `.gitattributes` plus `core.autocrlf=false` would have forced.
Consequences: `npm run check` is now a meaningful pre-push command and CI can be treated as blocking. `.prettierignore` is load-bearing and will look inconsistent until the games are swept - the ratchet comment in the file explains why. Lint still tolerates 16 warnings (dead code and unused `catch` bindings), so drift can accumulate as warnings; adding `--max-warnings 0` is the follow-up once that dead code is addressed. `public/games/yatsy/**` is ignored by Prettier even though Yatzy is actively developed, which is the one arguable exclusion: it is the largest single file in the repo (2077 lines, 2278 would change). Four real defects surfaced and were fixed in `public/games/millionaire/app.js`: two duplicate object keys, eight useless escapes, and a U+202F narrow no-break space inside a comment.
Alternatives_Rejected: Reformatting all 101 files in one dedicated commit - offered, and declined by the user in favour of the maintained-surface scope. Making `format:check` non-blocking or moving it after the build - rejected as a gate that reports nothing. Raising `printWidth` from 80 to 100 - measured (it would cut churn from 20,633 to 18,075 lines) but not applied, since changing a formatting convention is the user's call and the benefit disappears once the sweep is done. Adding `.gitattributes` with `* text=auto eol=lf` - the more canonical fix for the CRLF problem, but it renormalises the entire working tree on next checkout, which is far too invasive to mix with undeployed security work.
