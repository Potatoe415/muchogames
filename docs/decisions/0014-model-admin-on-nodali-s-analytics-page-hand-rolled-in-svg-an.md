# 0014 — Model /admin on nodali's analytics page, hand-rolled in SVG and scoped to the data actually stored

Date: 2026-08-30
Status: Accepted
Decision: Rebuilt `/admin` on the model of the `nodali` project's `cms/analytics` page, limited to a 7d/30d/6m range switch plus a daily trend chart, with the chart hand-written as one SVG polyline in a new `public/admin/trend-chart.js` and no charting library added. `POST /api/admin/stats` now accepts a `range`, and its `totalLaunches` is windowed instead of all-time.
Context: The user asked for nodali's statistics page to serve as the model for the games hub. That page offers a range switch, a live visitor badge polling every 20s, three stat cards (views, unique visitors, pages per visit), a daily trend chart with a hover tooltip, and ranked lists of pages, referrers, devices, countries and button clicks, split across tabs.
Rationale: Two constraints decided the scope. First, nodali is Next.js with React, Tailwind and shadcn/ui, while this admin page is plain HTML/CSS/JS copied verbatim out of `public/` with no build step, so the code cannot be ported at all - only the model. Second, and decisive, `muchogames_events` stores just `game_id` and `created_at`: of nodali's eleven elements, only the range switch, the daily trend, the total and the ranking are computable. Unique visitors, sessions, live presence, devices, countries and referrers would each need new columns, a change to `api/track.js`, and the collection of markedly more personal data (persistent visitor id, country, device) on a family party-game hub. That was put to the user, who chose the bounded scope.
Consequences: `totalLaunches` changed meaning, from an all-time count to a windowed one - hence the new caption under the figure naming the active period, so the number is never ambiguous. An unknown `range` falls back to the default rather than answering 400, since the only caller is our own page. Days are bucketed in UTC, so for a UTC+1/+2 audience a launch after midnight lands on the previous day; accepted, the trend shows shape rather than serving as an accounting record. The `MAX_ROWS` cap of 10,000 now applies per range rather than to all history, which makes it safer than before. The chart went into its own module because `admin.js` would otherwise have crossed the 300-line limit; `admin.css` is now at 271 effective lines, so the next addition there should split the file rather than grow it.
Alternatives_Rejected: Adding a charting library such as Chart.js - rejected on two counts: the page has no build step, so it would mean another unpinned CDN import, and `docs/BACKLOG.md` already tracks removing the one that exists (`esm.sh` in `yatsy/matchmaking.js`); roughly 60 lines of SVG avoids both. Aggregating in Postgres through a view or RPC - unnecessary at this volume and it would add a migration for no gain. Keeping an all-time total beside the windowed one - rejected, two similar figures with nothing to distinguish them at a glance. Adopting nodali's tabs - put to the user and declined, since two data families do not justify them. Extending the data model to match nodali fully - put to the user and declined.
